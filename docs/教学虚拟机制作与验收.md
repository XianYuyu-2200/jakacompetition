# 教学虚拟机制作与验收

状态：交付准备工具与流程，尚无已验收 OVA。适用基础组固定姿态教学，不连接 JAKA Mini 2、Gemini 305 或实体夹爪。

## 1. 交付内容与边界

采用「教师制作母版、学生导入副本」的方式。当前目标为 Ubuntu 22.04 amd64 桌面环境、ROS 2 Humble、Gazebo Fortress。先固定一种虚拟化软件及其版本，在 Windows Intel/AMD 学生电脑上完成验收；暂不承诺 Apple Silicon、ARM 客体或其他系统组合。

初始测试资源：4 vCPU、8GB 客体内存、80GB 虚拟磁盘、3D 加速。优先用 32GB 内存宿主机建立基线，再测试 16GB 宿主机。它们是测试起点，不是经过测量的最低配置。不要把全部宿主机资源分配给虚拟机。

仿真工件仍使用规划场景附着/镜像，6/6 表示程序与事件判分通过，不表示物理摩擦夹持成立。二维码来自生成的 PNG，不是内置相机实时扫描；相机画面用于观察。

## 2. 教师准备母版

1. 新建 Ubuntu 22.04 amd64 桌面虚拟机，启用虚拟化软件提供的 3D 加速，安装与该虚拟化软件匹配的客体工具。优先选择「Ubuntu on Xorg」会话，用于现有窗口嵌入验收。
2. 无需手动预装 ROS；新安装入口会配置官方签名软件源并安装 ROS/Gazebo，详见《学生工作台一键安装》。已有教师母版的源配置会保留。
3. 在虚拟机内获取干净的项目源码，使用固定的教师审核提交。不要从开发者电脑复制 `jaka_ros2/build`、`install`、`log`，它们可能包含原路径。
4. 以将来运行工作台的普通用户执行：

```bash
cd /你的项目路径/codex-competition
bash setup/prepare-student-vm.sh --plan
# 仅在确认这是教学虚拟机后执行；安装依赖时需要 sudo。
bash setup/prepare-student-vm.sh --apply
```

`--plan` 是默认行为，不安装、不编译。`--apply` 转到新的一键安装入口，检查系统并配置官方源，安装 ROS 和依赖、编译、创建当前用户快捷方式、运行只读预检。不会启动仿真、运行机械臂、重置配置或创建 OVA。软件源或编译失败时直接停止，不假装完成。整个过程需要网络；学生日常仿真不应依赖临时下载包，断网能力仍须在验收时实际检查。

5. 在虚拟机图形终端保存检查报告：

```bash
bash setup/run-workbench.sh --vm-check > "$HOME/workbench-vm-preflight.json"
```

`--check` 仍保持原有轻量元数据检查；`--vm-check` 额外执行有超时的只读 `glxinfo -B`、虚拟化类型、软件包版本和 Git 版本查询。两者均不启动 ROS 或仿真。报告中的 `simulation_acceptance` 与 `hardware_acceptance` 固定为 `not_run`，退出码 0 不代表运动验收通过。

检查重点：
- `error`：目标系统/架构不匹配、无 X11 DISPLAY、缺少必要模块或图形上下文不可用，先处理再验收。
- `warning`：软件渲染、低资源、未知虚拟化类型、Wayland 或环境变量覆盖等，需要人工核实。
- OpenGL 版本只能做前置诊断，不能证明 Ogre 所需扩展或相机渲染可用。不要用 `MESA_GL_VERSION_OVERRIDE` 伪装成通过，不自动关闭碰撞检查。

## 3. 母版验收与导出

先按《学生虚拟机入门与验收》完成全部操作，再运行隔离回放（会执行仿真机械臂运动）：

```bash
/usr/bin/python3 verification/accept_workbench_fixed_poses.py \
  --poses jaka_competition_kit/config/track1_simulation_example.yaml \
  --output "$HOME/workbench-vm-evidence-$(date +%Y%m%d-%H%M%S)" \
  --domain 94 --check-gripper-stall
```

这一步不验证窗口嵌入是否可见，必须同时留存人工界面验收记录。虚拟机过慢导致超时也属于该配置未通过，不得把删除超时或减少验收项当作性能修复。

导出前人工审核，不用脚本自动擦除整台机器：

- 关闭工作台与其启动的仿真，确认没有运行中的 ROS/Gazebo。
- 用专用教学账户制作母版，不在其中保存教师 SSH 私钥、浏览器登录、Git 凭据、真实设备地址或现场标定数据；有凭据污染时重建干净母版。
- 仿真配置必须保持 simulation profile；不要预置 hardware 配置。保留明确的官方基础姿态来源。
- 保存源码提交、软件包版本、预检、回放和人工验收记录。保留失败记录，不只挑通过的一次。
- 不在母版里保存运行中的挂起状态。正常关机后使用虚拟化软件导出为其支持的分发格式。
- 不因镜像分发自动修改机器 ID、密码、网络和共享目录；采用该虚拟化软件明确支持的导入/克隆流程。初期使用 NAT，不启用 USB 机器人设备透传或比赛网络桥接。
- 对分发文件运行 `sha256sum 文件名`，将哈希、镜像版本、宿主/客体条件和教程一同提供给学生。
- 在另一台电脑全新导入，检查快捷方式绝对路径、依赖、断网启动和持久化。只在制作者电脑上打开不算完成分发验收。
