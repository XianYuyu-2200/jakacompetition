# 决赛(真机)部署指南 —— JAKA Mini 2

> 适用:初赛(仿真)跑通之后,把同一份参赛程序搬到真机上。
> 核心结论:**仿真与真机走的是同一个 MoveIt 接口**,需要改的只有"启动什么",
> 不需要改一行算法代码。

---

## 0. 一句话对照

| | 初赛(仿真) | 决赛(真机) |
|---|---|---|
| 机械臂侧 | `demo.launch.py use_rviz_sim:=true` | `jaka_planner moveit_server.launch.py ip:=<ip> model:=minicobo`<br>+ `demo.launch.py`(**不带** `use_rviz_sim`) |
| 判分侧 | `judge.launch.py` | **同一份** `judge.launch.py` |
| 参赛程序 | `ref_track1` / 队伍自己的包 | **同一份**,只是 `-p gripper:=jaka_io` |
| 赛场定义 | `arena.yaml` | **同一份** `arena.yaml` |
| 轨迹接口 | `/jaka_minicobo_controller/follow_joint_trajectory` | **同名** |

MoveIt 的规划请求(`/move_action`)、场景接口(`/apply_planning_scene`)、
动作名(`/jaka_minicobo_controller/follow_joint_trajectory`)两边完全一样 ——
`jaka_planner` 就是照着 MoveIt 的标准接口实现的。

## 1. 网络与前置检查

```bash
# 1) 电脑与机械臂在同一网段(示例:机械臂 192.168.0.101,电脑 192.168.0.10)
ip a                      # 确认有线网卡的 IP
ping -c 3 192.168.0.101   # 通不了后面全部白搭

# 2) 确认机械臂的 IP(示教器:设置 -> 网络)
```

**注意**:`jaka_driver` 与 `jaka_planner` **不能同时运行** ——
两者都会独占机械臂的 10001/10003 控制端口,先起的那个会占住不放,
后起的会连接失败或行为异常。比赛前务必:

```bash
pkill -f jaka_driver ; pkill -f jaka_planner ; sleep 3
```

## 2. 启动顺序(每个都是独立终端)

```bash
source /opt/ros/humble/setup.bash
source ~/codex/codex-competition/jaka_ros2/install/setup.bash

# --- 终端 1: 机械臂侧(轨迹执行服务) ---
ros2 launch jaka_planner moveit_server.launch.py ip:=192.168.0.101 model:=minicobo

# --- 终端 2: MoveIt 规划 + RViz(不带 use_rviz_sim, 才是真机模式) ---
ros2 launch jaka_minicobo_moveit_config demo.launch.py

# --- 终端 3: 判分侧(与仿真完全一致) ---
ros2 launch jaka_competition_kit judge.launch.py \
    track:=1 seed:=-1 team:=你的队名 round:=FINAL

# --- 终端 4: 参赛程序 ---
ros2 run jaka_competition_kit ref_track1 --ros-args -p vel_scale:=0.5 \
    -p gripper:=jaka_io
```

> `use_rviz_sim:=true` 会让 MoveIt 用**假硬件**(只发轨迹不真动)。
> 真机模式必须**不带**这个参数,否则程序"跑得挺好,机械臂纹丝不动"。

## 3. 比赛流程(真机)

```bash
# 裁判出题(随机种子)
ros2 service call /competition/generate std_srvs/srv/Trigger "{}"

# 裁判发令, 自动开始计时
ros2 service call /competition/start std_srvs/srv/Trigger "{}"

# 出意外 -> 立即终止本轮
ros2 service call /competition/abort std_srvs/srv/Trigger "{}"

# 清判分状态 / 清场景(下一轮之前)
ros2 service call /competition/run/reset   std_srvs/srv/Trigger "{}"
ros2 service call /competition/scene/reset std_srvs/srv/Trigger "{}"
```

成绩自动写到 `~/.ros/jaka_competition/score_<时间戳>.json` / `.txt`。

## 4. 真机与仿真的差异清单(必须逐条处理)

| 项 | 仿真 | 真机 | 处理办法 |
|---|---|---|---|
| **夹爪** | `MockGripper` 只记状态 | 官方仓库**没有夹爪驱动** | 见第 5 节 |
| **碰撞** | 规划器拒绝轨迹 | 控制器报碰撞并**停机** | 触发后按"终止本轮"处理,须人工复位 |
| **负载** | 无 | 超过 2kg 会报警/掉电 | 赛前 `set_payload`(见第 6 节) |
| **精度** | 理想 | 重复定位 ±0.1mm | 工位留 50mm 间隙,已足够 |
| **速度** | 想多快都行 | 高速时抖动、过冲 | 真机速度缩放 ≤ 50%(见附录 B) |
| **工件** | 碰撞体 | 真实物品 | 固定工件,防止滚落 |
| **停止** | Ctrl+C | 必须用**物理急停** | 急停按钮由裁判掌握 |

## 5. 夹爪接入(真机唯一的"缺口")

本仓库**不含夹爪驱动**。三种可行路线,按推荐度排序:

### 路线 A(推荐):夹爪自带 ROS 驱动 / 串口工具

大多数电动平行夹爪(大寰、因时、Robotiq 等)都提供 ROS 2 包或串口协议。
写一个 20 行的 `Gripper` 子类接进去即可:

```python
from jaka_competition_kit.gripper import Gripper

class MyGripper(Gripper):
    name = "my_gripper"

    def __init__(self, node, port="/dev/ttyUSB0"):
        self.driver = MyGripperDriver(port)     # 你的驱动

    def open(self) -> bool:
        return self.driver.set_position(0.030)  # 30mm 行程

    def close(self) -> bool:
        return self.driver.set_position(0.0)
```

然后在参赛程序里把 `Executor(..., gripper=MyGripper(node))` 换掉即可。

### 路线 B:走机械臂的工具端数字 IO

MiniCab 控制柜有工具端 IO,可以直接给夹爪发"开/合"电平。
工具包里已经写好 `JakaIOGripper`,改两个参数就能用:

```bash
ros2 run jaka_competition_kit ref_track1 --ros-args \
    -p gripper:=jaka_io \
    -p io_index:=0 -p open_level:=false -p closed_level:=true
```

> ⚠️ `JakaIOGripper` 走的是 `jaka_driver` 的 `/jaka_driver/set_io` 服务。
> 而真机运动走的是 `jaka_planner` —— **两者不能同时运行**。
> 所以路线 B 只在"夹爪有自己的 IO 通道、与 jaka_planner 不冲突"时才成立;
> 否则请用路线 A 或路线 C。

### 路线 C:机械臂 IO 直接由 jaka_planner 侧的 SDK 调用

如果你的 `jaka_planner` 版本暴露了 IO 服务,直接调它即可 ——
这样夹爪和运动共用一个连接,不会抢端口。

**无论哪条路线,`Gripper` 只需要实现 `open()` 和 `close()` 两个方法。**

## 6. 赛前必做的三项真机配置

### 6.1 设置负载(否则会报警或掉电)

```bash
ros2 service call /jaka_driver/set_payload jaka_msgs/srv/SetPayload \
  "{payload: 0.6, x: 0.0, y: 0.0, z: 0.05}"
```

参数含义:夹爪 + 工件的总质量(kg)与质心在末端坐标系下的位置(m)。
**赛道一**约 0.5–0.7kg;**赛道二**最重工件 0.2kg,建议按实际称重设。

### 6.2 设置工具坐标系

```bash
ros2 service call /jaka_driver/set_tcp_frame jaka_msgs/srv/SetTcpFrame \
  "{tcp_offset: [0.0, 0.0, 0.04, 0.0, 0.0, 0.0]}"
```

`arena.yaml` 里的 `tool.flange_height: 0.040` 就是按"TCP 在法兰下方 40mm"
标定的。**如果你换了夹爪,这个值必须重新量、并在 `arena.yaml` 里改**,
否则抓取高度全错、法兰会插进工件里。

### 6.3 逐点空跑校核(不执行,只规划)

```bash
# 赛道一: 6 个工位
ros2 launch jaka_competition_kit selfcheck.launch.py track:=1 vel_scale:=0.3

# 赛道二: 12 件散放
ros2 launch jaka_competition_kit selfcheck.launch.py track:=2 vel_scale:=0.3
```

它对每个抓取点做一次规划(**不执行**),所以真机上也敢跑,而且
**不需要裁判发令、不计时**。**全部 OK 才允许开赛**;
有任何一个失败,说明场地摆放或 `arena.yaml` 与真机不一致。

> `selfcheck` 依赖 `/competition/scene`(题目真值),所以要先让
> `scene_generator` 出一个题 —— 也就是先跑一次
> `ros2 service call /competition/generate std_srvs/srv/Trigger "{}"`。
> 想看到场上摆位,再开 `ros2 launch jaka_competition_kit competition_rviz.launch.py`。

## 7. 急停与安全

1. 物理急停按钮**独立于机械臂**,由裁判掌握;
2. 真机速度缩放:常规 ≤ 50%,接近作业带边界时 ≤ 30%;
3. 触发碰撞停机 → 排除故障、复位后才能继续;累计 3 次直接终止本轮;
4. 运动范围内不得放置非比赛物品,选手席距机械臂 ≥ 800mm;
5. 首次真机联调**务必先跑 `verify_only:=true`**(只规划不执行),
   确认轨迹合理再放开真动。

---

## 7.5 真机上的限时怎么定

`rules.yaml` 里的限时(**赛道一 145s / 赛道二 320s**)是在**本仓库开发机**上
用参考实现标出来的,对应关系是"限时 = 实测中位数 × 1.4、效率满分线 = 中位数"。

**真机会比仿真慢**(控制器插补、真实加减速、安全限速、夹爪开合都是实打实的),
所以正式比赛前必须用真机重新标定:

```bash
bash design/calibrate.sh 1 3     # 真机上跑 3 轮
bash design/calibrate.sh 2 3
```

把脚本打印的"建议限时"填回 `config/rules.yaml`,并同步 `competition.md`。
**不要照抄仿真或者别的机器的数字。**

## 8. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 机械臂不动,程序却"成功" | 忘了去掉 `use_rviz_sim` | 重启终端 2 的 demo.launch |
| 连不上机械臂 | IP 错 / 网段不同 / 被 `jaka_driver` 占用 | `ping` + `pkill jaka_driver` |
| 所有抓取都报 -2 | 末端挂着幽灵工件 | 重启 `judge`,或调 `/competition/scene/reset` |
| 抓取点偏高/偏低 | `tool.flange_height` 与实际夹爪不符 | 重新测量并改 `arena.yaml` |
| 规划一直超时 | 工位超界 | `ros2 run jaka_competition_kit arena_check` |
| 夹爪不动 | `JakaIOGripper` 的 IO 号/电平不对 | 改 `io_index` / `open_level` |
