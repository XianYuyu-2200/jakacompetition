# 学生工作台一键安装

交付类型：**联网源码安装包**，适用于基础组固定工位、二维码顺序和关节姿态练习。包含工作台、仿真源码、模型资源、基础姿态示例和安装脚本。**不是 Windows 安装程序、离线依赖包或已验收 OVA**，首次安装需要网络与 sudo。

## 推荐：双击图标安装，不输入命令

安装包内新增 **「一键安装工作台.desktop」**，相当于 Ubuntu 下的安装启动图标。它必须在 **Ubuntu 虚拟机里打开**，不是 Windows 宿主机上的 `.exe`。

1. 在 Ubuntu 文件管理器中打开教师提供的压缩包，解压到「主文件夹」，最终目录应为 `~/jaka-student`。不要在 Windows 中解压，不要只复制启动图标而漏掉源码。
2. 打开 `jaka-student` 文件夹，将「一键安装工作台.desktop」复制到 Ubuntu **桌面**。
3. 如果系统要求信任该文件，右键选择「允许启动」；必要时在「属性 → 权限」中允许作为程序执行。只对教师提供、校验过的安装包确认。部分文件管理器不会从普通文件夹直接执行 `.desktop`，因此建议复制到桌面。
4. 双击 **「一键安装基础组工作台」**。它会自动打开终端，执行已有的一键安装流程；学生不需要输入安装命令。按提示输入 Ubuntu 账户的 sudo 密码（输入时不显示字符），等待安装结束。
5. 成功或失败都会保留窗口，按回车才关闭，避免报错一闪而过。失败时保留日志，修复后可再次双击。成功后从应用菜单打开「基础组学习工作台」。

首次「允许启动」和管理员密码属于系统安全确认，不会由脚本绕过。启动文件只依赖系统 Python 3 和桌面终端，不依赖尚未安装的 PyQt5、ROS、pip 或 Git。安装完成不会自动启动仿真或连接真机。安装后仍须保留 `~/jaka-student` 源码目录。

## 备用：终端安装

1. 创建 **Ubuntu 22.04 amd64 桌面版**虚拟机，进入图形桌面。无需预装 ROS、Gazebo 或 Python pip 环境。建议测试起点为 4 vCPU、8GB 内存、80GB 虚拟磁盘和 3D 加速；实际性能仍需在学生电脑验收。安装脚本要求源码盘至少剩余 15GiB、系统盘至少剩余 10GiB。
2. 将教师提供的 `jaka-student-<版本>.tar.gz` 和同名 `.sha256` 文件复制到 Ubuntu 下载目录。在 **Ubuntu 内**校验并解压，不要先在 Windows 解压，也不要直接在虚拟机共享目录编译。

```bash
# 将 <版本> 换成文件名上的版本，校验输出必须是 OK。
cd ~/Downloads
sha256sum -c jaka-student-<版本>.tar.gz.sha256
# 首次安装：目标 ~/jaka-student 不应已存在；升级请另选目录，勿覆盖个人修改。
tar -xzf jaka-student-<版本>.tar.gz -C "$HOME"
cd ~/jaka-student
bash setup/install-student.sh --install
```

中文桌面的下载目录可能叫 `下载`；也可以在文件管理器打开压缩包所在目录，再「在终端打开」。**不要用 sudo 启动整个脚本**，安装依赖时脚本会申请权限。安装可能下载数 GB，时间取决于网络和虚拟机性能。

已经拿到源码的学生，只需在项目根目录执行同一条安装命令。不带参数或使用 `--plan` 只显示计划，不修改系统。

3. 安装完成后，从应用菜单或桌面打开 **「基础组学习工作台」**。桌面提示不可信时右键「允许启动」。解压目录即实际安装目录，**不能删除**；移动目录后需要重新编译并安装快捷方式。
4. 优先使用登录界面的「Ubuntu on Xorg」会话，开启虚拟机 3D 加速并安装虚拟化软件配套客体工具。脚本不自动更换显示驱动、安装客体工具或伪装 OpenGL 版本。
5. 按《学生虚拟机入门与验收》点击环境自检、启动环境、检查内置 Gazebo/相机、载入仿真基础姿态并完成六工位流程。

## 自动安装了什么

| 阶段 | 内容 |
|---|---|
| 系统前置 | 系统/架构/空间/源码检查，Ubuntu universe，编译工具与中文字体 |
| 软件源 | ROS 官方 ros2-apt-source 固定 1.3.0，下载后校验 SHA-256；Gazebo 官方源使用独立 keyring 并校验主密钥指纹 |
| ROS / 仿真 | ROS 2 Humble Desktop、MoveIt、ROS 控制器、ros_gz、ign_ros2_control、Ignition Fortress |
| 工作台 / 相机 | PyQt5、OpenCV、cv_bridge、NumPy、Pillow、PyYAML、二维码生成与解码、OpenGL 诊断工具 |
| 本地构建 | 在解压目录编译；包级串行、编译器最多两个并发任务，不复制开发机 build/install |
| 收尾 | 当前账户快捷方式、依赖版本表、安装结果与只读 VM 预检 |

脚本不执行远程 shell 脚本；下载的 ROS 软件源 `.deb` 在哈希验证后才会执行其安装流程。APT 安装保留签名校验，不使用 `trusted=yes` 或 `--allow-unauthenticated`。已有 ROS/Gazebo 源会保留；遇到过期密钥或源冲突会停止，由教师处理，不自动删除旧源。软件源安装和 apt 依赖不是完全冻结的离线快照，版本表用于追溯。

会定向升级已安装的 systemd、systemd-sysv、udev，以处理 ROS 官方文档提醒的早期 Jammy 依赖问题；不做全系统 `apt upgrade`。不修改 `.bashrc`、用户姿态、真实设备标定、碰撞检查或系统 MoveIt Python 文件。工作台仿真 launch 本身不依赖旧的全局 MoveIt 补丁；旧教程的独立 demo 命令不在此安装入口验收范围。

## 失败后怎么办

安装日志默认在 `~/.local/state/jaka-workbench/install-时间-随机后缀/`（设置了 `XDG_STATE_HOME` 时使用该目录）。包含：

- `install.log`：命令与输出，安装开始时会打印可复制的 `tail -f` 查看命令。
- `packages.tsv`：依赖安装与编译完成后的软件包版本表。
- `vm-preflight.json`：执行到收尾预检时保存的报告。
- `result.json`：安装成功或失败；仿真/真机验收均单独标记 `not_run`。

下载或 APT 失败时检查虚拟机联网和官方源访问，不要使用关闭签名验证的办法。编译失败先看日志；内存不足时增大客体内存，空间不足先扩容。不要删除学生自己保存的姿态。修复原因后可执行同一条安装命令，APT 和构建会复用已完成部分；不跳过曾失败的步骤。

预检失败也会返回非零退出码，不能当成安装验收通过。缺少 DISPLAY 时从 Ubuntu 图形终端重跑；黑屏/软件渲染/嵌入窗口异常需检查 Xorg、3D 和客体工具。无论安装退出码是否为 0，都还要实际验证 Gazebo、相机和完整六工位流程。

## 教师怎么生成安装包

在审核过的源码仓库运行：

```bash
/usr/bin/python3 setup/package-student.py --version 20261114-candidate
```

产物默认写到 `dist/`，同时输出 `.tar.gz` 和 `.sha256`。打包器只选择允许范围内的 Git 跟踪文件及明确列出的新安装文件，不纳入开发机 `.git`、构建目录、运行数据、虚拟环境和训练权重。保留仓库内相对符号链接，拒绝绝对路径或指向仓库外部的链接。包内 `PACKAGE-MANIFEST.json` 记录基础提交、工作树是否有修改以及每个文件的 SHA-256/链接目标；外部 `.sha256` 用于传输校验，不是发布者数字签名。

打包脚本不会覆盖已有同名压缩包。分发前在干净虚拟机完成一次安装、快捷方式启动、Gazebo/相机、多个二维码顺序、姿态保存和断网运行验收，并保留报告。**当前只有安装候选包；不能把本机软件测试或压缩包校验写成学生 VM 验收通过。**
