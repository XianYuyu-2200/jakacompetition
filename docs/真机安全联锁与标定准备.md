# 真机安全联锁与标定准备（待现场验证）

## 当前边界

工作台当前只用于学习仿真，**不允许连接真机进行工作台运动试验**。软件停止、ROS 域隔离、`simulation` 字符串和 MoveIt 碰撞检查都不是安全联锁，也不能替代实体急停或现场风险评估。将真机控制器暴露到工作台所在 ROS 图时，即使界面选择仿真，也不能证明动作只会到达仿真设备。

仓库中的 `jaka_planner/include/jaka_planner/jktypes.h` 声明了 `RobotStatus` 的 `emergency_stop` 和 `protective_stop` 字段；`jaka_msgs/msg/RobotMsg.msg` 仅包含运动、电源、伺服、碰撞四个字段。`jaka_planner/src/moveit_server.cpp` 中存在 `get_robot_status` 调用，但当前仓库证据不足以确认这些安全状态已经提供给运动许可链路、字段语义与具体固件的对应关系或现场可用性。不能据此宣称已经实现真机联锁。

## 设备接入前需要确认

由设备负责人、赛事安全负责人和操作员共同确认并留档：

- Mini 2 控制器、固件与驱动版本，Gemini 305 与夹爪的实际型号、安装方式、电气连接和厂家文档。
- 现场风险评估、工作空间和防护措施、实体急停位置及测试方法、人工接管方式。工作台退出、网络断开和软件停止不等于急停。
- 官方接口中连接、控制模式、使能、急停、保护停止、故障和状态时间戳的具体来源与语义，包括状态过期、通信失败和重连时的行为；未知项一律不许可运动。
- 硬件 profile、机器人序列号、工具/TCP、夹爪参数和工作台坐标系。仿真关节角只可供学习，不能作为真机已校准数据。

## 实施要求与验收

1. 在硬件安全防护已就绪、具有明确权限的环境中，先做只读状态采集；核对急停、保护停止、故障、断线和状态过期的观测结果。不发送运动、上电或复位指令。
2. 设计独立、默认拒绝的运动许可链：显式选择目标设备与硬件 profile、有效状态、设备及现场确认；任何未知、过期、断线或故障状态应阻止新动作。运动中状态变化的停机行为须由设备厂商和现场安全负责人审核，不能仅依赖 Python/ROS 实现安全功能。
3. 先验证硬件急停与防护装置，再按设备手册和现场安全流程做低速、受控的标定。记录相机内外参、工具/TCP、基座与工位坐标、逐工位关节姿态、夹爪参数及配置版本；核验后才允许用于比赛。
4. 验收包含断线、状态过期、急停、保护停止、重启和错误 profile；需要现场证据和负责人签字。没有设备及核实后的安全信号时，这些项目保持未完成。
