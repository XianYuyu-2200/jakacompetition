# 怎么把这两个比赛办起来

> 现行规则在 `competition.md`,赛场在 `jaka_competition_kit/config/arena.yaml`,
> 分值与限时在 `config/rules.yaml`。校核过程(含已经作废的 12 件 / 320 秒赛道二)
> 在 `规则校核报告.md`,看现行数字直接翻到**附四**。
> 本文只保留还在用的落地约定:哪些已经做成了,哪些还没做。

---

## 第 0 步:三个已经定下来的决定

**决定 1 — 初赛仿真,决赛真机。**

一台 Mini 2 只能给一队用;仿真可以并发,也避免现场标定差异变成判罚争议。
初赛判分线是 **ROS 2 Humble + MoveIt 2 假硬件**。Gazebo 只做转播画面
(`round.launch.py world:=gazebo`),不参与判分,限时也不能照搬。
决赛用同一份 `arena.yaml`、同一套评分程序,部署步骤在 `docs/真机部署.md`。

**决定 2 — 选手交付一个 ROS 2 功能包,或往官方工具包里填解法。**

官方包是 `jaka_competition_kit`。参考实现走的是 `Executor.pick_and_place`,
感知结果在真实比赛里要选手自己估;`/competition/scene` 里的位姿和类别是**出题真值**,
给裁判和参考实现用,不代表视觉成绩。

没有做成当初草拟的 `decide(scene) -> list[Grasp]` 插件接口。
队伍直接调抓取原语即可,见工具包 README 第 4 节。

**决定 3 — 计时和判分自动做。**

赛道一是 6 个工位按二维码顺序;赛道二是 **16 件、四类**,放错盒子不计分。
人工判顺序、类别和掉落一定会出错。仿真侧已经自动判;真机的称重和掉落复核还没有。

## 第 1 步:赛场与硬件

### 1.1 硬约束

**工具轴竖直向下时,可达作业带是距基座 180–420 mm。**
矩形区域必须判**最近点**,不能只看四角。料盒只判**中心**。
改任何尺寸后跑 `ros2 run jaka_competition_kit arena_check`。

### 1.2 台面与安装

| 项目 | 现行 | 说明 |
|---|---|---|
| 坐标系 | 基座安装面中心为原点,台面 = z=0,+y 指向工位 | 基座直接固定在台面上 |
| 台面 | 900×700 mm,中心约 (-20, 300) | `arena.yaml` 的 `table` |
| 台面高度 | 上表面略低于基座安装面(`top_z = -1 mm`) | 避免贴面误判碰撞 |
| 相机 | 台面正上方 700–900 mm,刚性俯拍 | 赛道一读二维码;赛道二可用深度相机 |

基座如果改成立柱、台面低于基座,整张可达域都要重跑
`verification/reach_scan.py` 和 `near_scan.py`。

### 1.3 每条赛道的配置

| 类别 | 规格 | 备注 |
|---|---|---|
| 机械臂 | JAKA Mini 2,6 轴,负载 2 kg,臂展 580 mm,重复定位精度 ±0.1 mm | 仿真用 `jaka_minicobo` URDF,运动学一致 |
| 末端(规则书默认) | 电动平行夹爪,行程 0–30 mm | `arena.yaml` 的 `tool.gripper: none`,按 40 mm 法兰高度留余量 |
| 末端(已接入的实物方案) | WHEELTEC MS42DC 柔性二指爪,可夹约 24–70 mm | `JAKA_GRIPPER=1`;指尖深 164.6 mm,抓取高度约抬 74 mm。见 `docs/WHEELTEC柔性机械爪.md` |
| 视觉 · 赛道一 | 单目 1280×720,眼在手外 | 只读二维码,机械臂不去够卡片 |
| 视觉 · 赛道二 | Intel RealSense D435i,或自备 | 允许接大模型 API。官方**不提供**检测模型 |
| 工位 | 6 块 100×100 mm 标记板 | 仅赛道一 |
| 工件 · 赛道一 | 6 种规则几何体,单重 ≤50 g | 固定在工位中心 |
| 工件 · 赛道二 | 20 种,四类各 5 种;仿真是包围盒,高度 ≤40 mm | 每类 5 选 4,共 16 件 |
| 料盒 · 赛道一 | 1 个 200×150×40 mm | 中心 (315, 180) |
| 料盒 · 赛道二 | 4 个,各 130×110×40 mm | 生活 / 工具 / 玩具 / 水果 |
| 急停 | 独立于机械臂的物理按钮 | 裁判掌握;按下即终止本轮 |
| 录像 | 俯拍 + 侧拍 | 真机判罚取证。仿真不依赖它 |

`extras_linkerhand/` 是灵巧手 SDK,不是比赛夹爪。

### 1.4 布局(与 arena.yaml 一致)

赛道一,工位阵中心距基座 280 mm,中心间距 150 mm:

| 元素 | 中心 (x, y) mm | 距基座 |
|---|---|---|
| 工位 1 / 2 / 3 | (-150, 205) / (0, 205) / (150, 205) | 254 / 205 / 254 mm |
| 工位 4 / 5 / 6 | (-150, 355) / (0, 355) / (150, 355) | 385 / 355 / 385 mm |
| 料盒 | (315, 180),200×150×40 | 363 mm,只判中心 |
| 二维码 | (0, 110),60×60 | 110 mm,俯拍读取,机械臂够不到也不需要够 |

赛道二:

| 元素 | 中心 (x, y) mm | 说明 |
|---|---|---|
| 散放区 | (0, 278),380×175 | x∈[-190, 190],y∈[190, 365];最近点 190 mm,最远角 411 mm |
| 生活 / 工具 | (270, 125) / (-270, 125) | 各 130×110×40,r=298 mm |
| 玩具 / 水果 | (270, 245) / (-270, 245) | 各 130×110×40,r=365 mm |

生活盒、玩具盒和赛道一料盒重叠,工位板和散放区也重叠。
**场上只摆当前赛道。** 配图用 `python3 design/make_rulebook_figures.py` 重出,
不要用早期的 `arena_layout.png` 当现行赛场(那张还是原稿对比图)。

## 第 2 步:官方工具包 —— 已有的和还缺的

```

├── config/arena.yaml      赛场几何,唯一真源
├── config/rules.yaml      分值、限时、容差
├── arena / arena_check    读配置并校核作业带、末端高度
├── scene_generator        出题:二维码顺序 / 16 件四类抽签与货架装箱
├── qr                     JAKA1-###### 的生成、解析、PNG
├── scene / executor / backend / gripper
├── scorer                 计时、入盒、顺序、放错类、扣分、成绩单

├── ref_track1 / ref_track2
└── launch/                judge、round、selfcheck、gazebo_mirror
```

当初列的 4 件里,落地情况是:

| 件 | 状态 |
|---|---|
| 场景生成器(固定种子,两条赛道共用) | **已有**。`/competition/generate` |
| 手眼标定工具和重投影误差验收 | **没有**。赛题要求选手自己标定,官方没有 `calibrate` 命令 |

**继续不要提供**现成的视觉检测模型和抓取点生成。那是赛道二的考察点。
参考实现的类别直接读真值,成绩只能用来标限时,不能当成视觉方案的上限。

## 第 3 步:裁判与评分

仿真里这些已经自动做了(成绩在 `~/.ros/jaka_competition/`):

| 判分项 | 现在怎么判 |
|---|---|
| 抓取顺序(赛道一) | `grasp` 事件里的工位 ID 对二维码 |
| 是否入盒 | 释放点落在料盒内缩 20 mm 的范围里 |
| 类别(赛道二) | 必须落在该工件类别对应的那只料盒,放错不计基础分 |
| 掉落 | 松手时不在任何料盒内 |
| 碰撞 | 规划器报碰撞失败,由执行器上报 |
| 计时 | `/competition/start` 开始;全部入盒、超时或中止时停止 |

真机细则仍写"料盒称重 + 裁判复核"。称重传感器和俯拍掉落检测**还没做**。
最小可行的现场配置仍然是:顺序和计时用这套程序,入盒用称重或目视,碰撞和掉落由 1 名裁判对照录像复核。

现行分值:赛道一满分 100(基础 60 + 效率 40,145 秒 / 105 秒);赛道二满分 190(基础 160 + 效率 30,115 秒 / 85 秒)。创新加分另计,不进自动成绩单。

## 第 5 步:还在生效的坑

1. **仿真和真机不能同时跑。** `jaka_driver` 和 MoveIt 假硬件互斥。
2. **apt 升级 MoveIt 会覆盖 `launches.py`。** 升级后重跑 `setup/patch-moveit-launches.sh`,否则 `use_rviz_sim:=true` 被静默忽略,去连真机。
3. **两套仿真不能并存。** 重开前 `bash setup/sim-clean.sh`。launch 会检查冲突。
4. **`joint_2` 在 URDF 里是 ±119.7°,手册是 ±125°。** 贴着边界设计动作时,仿真和真机不一致。
5. **URDF 没有负载字段。** 真机赛前要 `set_payload` 和 `set_toolframe`。仿真靠规划场景里的碰撞体,不建动力学质量。
6. **换夹爪必须连抓取高度一起换。** 只改 URDF、不改 `arena.yaml` 的 `tool`,手指会扎进台面;长末端在工位 4/6 原地竖直抬不到转场高度,参考实现走 L 形。
7. **限时按判分那条线标定。** 假硬件赛道一中位数 102.7 秒,同一套参考实现在 Gazebo 里约 209 秒。
8. **`jaka_jog_panel` 缺失、`warehouse_ros_mongo` 没有 apt 包。** 不影响比赛,但选手照官方文档装环境会撞上。

- 真机入盒称重、掉落的相机复核。
- 请 2–3 支队试办,把规则里说不清的地方找出来。
