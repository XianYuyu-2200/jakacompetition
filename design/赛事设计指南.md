# 怎么把这两个比赛设计出来

> 前提:先读 `规则校核报告.md`。那里列了 `competition.md` 里必须改的地方,
> 本文讲的是**怎么把比赛真正落地**,顺序按"先定什么、后定什么"排。

---

## 第 0 步:先做三个决定,它们决定后面所有事

这三个问题不定,后面全是白干。

**决定 1 — 初赛用仿真还是真机?**

强烈建议 **初赛仿真 + 决赛真机**。理由:
- 一台 Mini 2 只能给一队用,30 支队就是 30 天;仿真可以无限并发。
- 仿真复现性好,不会因为现场温漂/标定差异产生判罚争议。
- 本仓库已经跑通了完整仿真链路(RViz 假硬件 + Gazebo 真物理),直接能用。
- 代价:需要自己写一个"比赛场景生成器"和"自动评分器"(见第 2、3 节)。

**决定 2 — 选手交付什么?**

三种规格,按你的组织和评审能力选:
| 规格 | 选手交付 | 现场做什么 | 适合 |
|---|---|---|---|
| A 全开放 | 一整个 ROS 2 功能包 | 部署 + 跑 | 省赛/国赛 |
| B 半开放 | 只填一个 `solve.py`(检测+抓取顺序) | 装进官方框架跑 | 区域赛,最推荐 |
| C 全封闭 | 不写代码 | 现场调参数 | 校赛,设备紧张 |

**推荐 B**:官方提供 `jaka_competition_kit` 包,选手只需要实现:
```python
def decide(scene) -> list[Grasp]:   # 输入感知结果, 输出抓取序列
def on_result(grasp, success): ...  # 回调, 用于重试逻辑
```
感知/运动/夹爪/异常处理全由官方框架兜底。这样考察点仍然清晰,
但不会因为"队伍卡在 ROS 环境"而全员零分。

**决定 3 — 成绩怎么算?**

**必须做自动计时 + 自动判分**,否则 6 个工位 × 12 个工件的人工判分
在现场一定出错、也一定会被质疑。见第 3 节。

## 第 1 步:赛场与硬件

### 1.1 核心约束(来自实测,不是估算)

**有效作业带:距基座水平距离 180–420mm,工具竖直向下时可达。**
超出这个环带,`/compute_ik` 直接失败。所有设备摆放都要按这条来。

细节数字见 `规则校核报告.md` 与 `README.md`;画图脚本在 `make_layout_figure.py`。

### 1.2 台面与安装

| 项目 | 建议 | 说明 |
|---|---|---|
| 基座安装 | 直接固定在台面上,基座面 = 台面 = z=0 | 本报告的坐标系就是按这个建的 |
| 台面尺寸 | ≥ 900 × 700mm | 够放 350×250 散放区 + 料盒 |
| 台面高度 | 距地 750–800mm | 常规站姿操作高度 |
| 相机支架 | 台面正上方 700–900mm,俯拍 | 需刚性固定,不能晃动 |

> 如果台面比基座**低**(基座装在立柱上),整个可达域会变。要么按本报告的
> 方案(基座直接在台面上),要么重新跑一遍 `reach_scan.py` / `near_scan.py`。

### 1.3 BOM(每条赛道配置)

| 类别 | 规格 | 数量 | 备注 |
|---|---|---|---|
| 机械臂 | JAKA Mini 2 | 1 | 赛道一/二相同 |
| 控制柜 | MiniCab(48V DC) | 1 | |
| 夹爪 | 电动平行夹爪,行程 0-30mm | 1 | 需 ROS 2 驱动;**原仓库没有夹爪驱动,要自备** |
| 相机(赛道一) | 单目工业相机 1280×720 | 1 | 俯拍,只需二维码识别 |
| 相机(赛道二) | Intel D435i | 1 | 深度 + RGB |
| 工位标定板 | 6 个 100×100mm 标记板 | 1 套 | 赛道一 |
| 工件(赛道一) | 6 种几何体,≤50g,工程塑料 | 3 套 | 备 3 套轮换 |
| 工件(赛道二) | 15-20 种日用品,≤200g | 3 套 | 见规则校核报告第 6 条 |
| 料盒 | 150×100×50(赛道一) / 200×150×100(赛道二) | 各 1 | 位置见 1.1 |
| 急停 | 独立于机械臂的急停按钮 | 1 | 必须;规则里的"终止"靠它 |
| 录像 | 俯拍 + 侧拍各 1 路 | 2 | 判罚取证用 |

> ⚠️ 原仓库 **没有夹爪 ROS 2 驱动**。这是赛道一最先要补的东西。
> `extras_linkerhand/` 里那个灵巧手 SDK 是"可选末端",不是标准平行夹爪,
> 别直接当成比赛夹爪。

### 1.4 布局(直接采用)

```
                     俯视  (相机高度 700-900mm, 需刚性固定)
 y (mm)  距基座方向
      ^
  480 |   +----------------------------------------------+
      |   |                                              |
  405 |   |     +----+   +----+   +----+                 |
      |   |     | 4  |   | 5  |   | 6  |   <- 远排 y=355  |
  305 |   |     +----+   +----+   +----+                 |
      |   |     +----+   +----+   +----+                 |
      |   |     | 1  |   | 2  |   | 3  |   <- 近排 y=205  |
  155 |   |     +----+   +----+   +----+       +------+  |
      |   |                                  | 料盒 |  |
  130 |   |         +--------+                 +------+  |
      |   |         | 二维码 |  <- 相机拍, 机械臂不需够   |
   55 |   |         +--------+                          |
      |   |                    ###                     |
      0 |   +-------------------###- JAKA Mini 2 -------+
      +--------------------------------------------------> x (mm)
         -450        -150    0    +150             +450
                       <--  工位中心间距 150mm  -->
                        ^^^ 工位阵中心距基座 280mm ^^^
```

- 工位中心:近排 `y=205`,远排 `y=355`;x 分别 `-150 / 0 / +150`
- 料盒中心:`(280, 180)` → r = 333mm ✔(余量 87mm)
- 二维码卡:与基座中轴线对齐、放在工位阵前方 → `(0, 130)`,r=130mm
  ⚠️ **注意**:原稿写"工位阵列正前方 100mm",按近排前缘 y=155 计算就是 y=55mm,
  已经贴到基座了。而且实测 z=30mm 时**最近可达半径是 180mm**,机械臂够不到。
  建议:二维码放 `(0, 130)` 由**俯拍相机**读取,**机械臂不需要去够它**。
  如果规则要求机械臂扫描二维码,那它必须放在 r ≥ 200mm 处。

## 第 2 步:软件 —— 官方 Starter Kit 该给什么

这是"设计比赛"里最重的一块。建议做成一个 ROS 2 功能包
`jaka_competition_kit`,赛道一/二共用底座,只换感知和决策模块。

```
jaka_competition_kit/
├── arena/            赛场定义(工位坐标/散放区/料盒), 一份 YAML
├── sim/              一键起仿真 + 自动摆件 + 复位
├── perception/       手眼标定工具 + 工件检测接口
├── executor/         抓取原语: approach / grasp / lift / place / release
├── scorer/           自动计时 + 判分 + 出成绩单
└── examples/         三档参考实现(弱/中/强), 供出题方校准难度
```

**必须提供的 4 件东西:**

1. **场景生成器**:一键摆好本轮工件(可选固定种子),保证每队遇到同样的局面。
   赛道一还要能随机生成二维码。
2. **手眼标定工具 + 验收指标**:`ros2 run ... calibrate` → 输出标定矩阵,
   同时给出"重投影误差 X mm"。**标定误差必须量化**,否则选手会说"我标好了但我没抓到"。
3. **执行原语的时间预算**:每个原语的实测耗时(见 `design/README.md` 的表),
   让选手能自己规划 6 个工件塞不塞得进 145 秒。
4. **仿真复位**:一轮结束 5 秒内回到初态,否则现场转场时间比比赛时间还长。

**不要提供的:**不要给现成的视觉检测模型、不要给现成的抓取点生成。
那正是赛道二的主要考察点。

## 第 3 步:裁判与自动评分系统

人工判 6 工位 × 12 工件的顺序、掉落、碰撞,**一定出错**。建议:

| 判分项 | 自动化方案 |
|---|---|
| 抓取顺序 | 执行器记录每次 grasp 的工位 ID + 时间戳,自动比对二维码顺序 |
| 是否放入料盒 | 料盒内加**称重传感器**(HX711 + 4 个应变片),每件 +重量;或料盒内加对射光电计数 |
| 掉落 | 俯拍相机 + 桌面背景差分:夹爪闭合期间工件投影从"夹持"变"桌面"即判掉落 |
| 碰撞 | 真机读控制器碰撞标志;仿真读 MoveIt 规划器返回的 `error_code` |
| 计时 | 裁判发令 → 自动开始;所有工件入盒或超时 → 自动停止 |

**最小可行版本**:顺序 + 计时自动(软件就能做),放入料盒用**称重**判,
碰撞和掉落由 1 名裁判目视 + 录像复核。这样 1 场比赛 2 个人就够。

**评分表模板**(每队一张):
```
队伍: ________   赛道: ___   轮次: ___   日期: ______
二维码内容: 2 4 6 1 3 5   实际顺序: ________
计时: 起始 ____:____.__  终止 ____:____.__  净用时 ______ s
工件 1..6:  入盒 ✔/✘    掉落 ✔/✘    顺序正确 ✔/✘
碰撞次数: ___  人工干预: ___ 次
基础分 ____ + 效率分 ____ - 扣分 ____ = 总分 ____
裁判签名: ______   选手签名: ______
```

## 第 4 步:分阶段实施路线

| 阶段 | 时间 | 产出 | 验收标准 |
|---|---|---|---|
| **P0 规则定稿** | 1 周 | 按 `规则校核报告.md` 改完 `competition.md` | 所有尺寸都在有效作业带内 |
| **P1 赛场数字孪生** | 1 周 | `arena/*.yaml` + 本目录的校核脚本全部转正 | `arena_report.py` 全绿 |
| **P2 参考实现** | 2 周 | 赛道一/二各一版能完整跑通的 `examples/` | 赛道一 6/6 且耗时已知;赛道二 ≥80% |
| **P3 限时标定** | 2 天 | 用 P2 在目标机器上跑 10 次取中位数 | 得到单轮限时与效率分门槛 |
| **P4 评分系统** | 2 周 | `scorer/` + 评分表 | 一场无人工干预的模拟赛跑完 |
| **P5 试办赛** | 1 天 | 请 2-3 队来打一场 | 找出规则里所有说不清的地方 |

**P3 最容易被跳过,但最关键**。现在 `competition.md` 里两个限时
(90s / 180s)都是拍脑袋定的,实测差了 1.5-3 倍。

## 第 5 步:已知的坑

1. **仿真和真机不能同时跑** — 官方文档明确写了,`jaka_driver` 和 MoveIt 假硬件互斥。
2. **改完 `moveit_configs_utils/launches.py` 后 apt 升级会覆盖** —
   每次升级 MoveIt 后要重跑 `setup/patch-moveit-launches.sh`,否则
   `use_rviz_sim:=true` 被静默忽略,会去连真机。
3. **Gazebo 模式下会多起一个崩溃的 `ros2_control_node`** — 无害,但日志很难看,
   建议在选手文档里提前说明,不然会被当成 bug 报上来。
4. **URDF 里 `joint_2` 行程是 ±119.7°,比官方 ±125° 小 5°** —
   如果赛场布局贴着边界设计,这 5° 会产生"仿真能过、真机边界不同"的差异。
5. **URDF 没有负载字段** — 赛道二工件最重 200g,建议在 SRDF / 规划场景里
   显式加 `AttachedCollisionObject` 的 payload,否则动力学仿真和真机手感对不上。
6. **`jaka_jog_panel` 缺失、`warehouse_ros_mongo` 没有 apt 包** —
   不影响比赛,但选手照官方文档装环境会撞到,提前在环境说明里写清。
7. **夹爪驱动要自备** — 见 1.3 的 ⚠️。
