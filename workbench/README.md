# 基础组学习工作台（Ubuntu 源码原型）

本目录提供现有基础组仿真的桌面操作入口。第一版复用已有 ROS 2、MoveIt、Gazebo、RViz 和参考程序，不更换核心抓取策略、Executor 或逆运动学算法。

**当前交付不是 Windows `.exe`、完整离线安装包、预装虚拟机或加密狗授权版本。** 复制工作台目录本身不等于安装了仿真环境；需要完整项目及已配置、已构建的依赖。第一版不自动安装软件，也不会停止用户原先启动的仿真。

## 运行条件

- 目标环境：Ubuntu 22.04、系统 Python 3.10、ROS 2 Humble、已构建的项目工作区。
- 界面使用 PyQt5；实际仿真需要可用的桌面图形会话。默认使用 `/usr/bin/python3`，避免误用缺少 ROS/Qt 的 Python 虚拟环境。
- `basic` 默认需要已构建的 Gazebo Fortress、MoveIt 和比赛工具包；Gazebo 主视图默认不启动 RViz。可在界面选择轻量假硬件/RViz 模式。
- `vision` 额外需要现有 Gazebo Fortress、YOLO 虚拟环境及基础组权重。权重与虚拟环境不随 Git 提交，仅克隆源码可能缺少这些文件。
- 不要求先在当前终端 `source` ROS；后台 ROS 命令由工作台自行加载环境。尚未构建时请由维护人员按项目说明构建；入口脚本不会代替构建。
- 尚未完成学生虚拟机配置矩阵测试，不承诺最低硬件、帧率、无碰撞或所有机器上的抓取成功率。

## 启动、自检和界面演示

在项目根目录运行：

```bash
# 只读 JSON 自检；不打开 UI、不启动仿真
bash setup/run-workbench.sh --check

# 基础练习界面
bash setup/run-workbench.sh --mode basic

# 演示界面与模拟流程，不启动真实 ROS/Gazebo 抓取
bash setup/run-workbench.sh --demo

# 基础组六类几何体识别；显示标注图像，无 YOLO 权重依赖
bash setup/run-workbench.sh --mode recognition

# 视觉练习模式；有额外运行依赖
bash setup/run-workbench.sh --mode vision
```

启动脚本根据自身位置查找项目根目录，不依赖终端当前目录。也可以从任意目录使用脚本绝对路径启动；路径含空格时需要给整段路径加引号。

可选参数：

```bash
bash setup/run-workbench.sh --root /项目目录 --data-dir /学习数据目录
```

默认数据目录为 `${XDG_DATA_HOME:-$HOME/.local/share}/jaka-workbench`，其中保存工作台运行日志等数据。可用 `WORKBENCH_PYTHON=/解释器路径` 覆盖 Python；必须是单个解释器路径，不是带参数的 shell 命令。

`--check` 仅检查安装文件、解释器可发现的依赖和环境信息；**检查通过不代表控制器、MoveIt、相机或 OpenGL 已经就绪**。实际启动仍可能失败，请结合工作台日志定位。若缺少 PyQt5，普通启动会输出人工安装提示；例如由管理员执行 `sudo apt install python3-pyqt5`。本脚本不会执行该命令。

## 三种模式的区别

| 模式 | 复用的仿真流程 | 能学到什么 | 不代表什么 |
| --- | --- | --- | --- |
| `basic` | 默认 MoveIt + Gazebo 机械臂/夹爪 + 基础组判分和赛场镜像；可切换轻量假硬件/RViz | 二维码给出六个固定工位的抓取顺序；在工作台调整关节角并记录固定姿态，训练数据可迁移到真机 | 工件目前由规划场景镜像跟随；仿真姿态不是 JAKA Mini 2 真机标定结果 |
| `recognition` | 现有 Gemini 305 专用识别场景 + 深度轮廓分类器 | 识别正方体、长方体、圆柱体、六角柱、三角柱、圆台；标框相机图与分类结果内嵌工作台 | 教学演示，不是正式比赛成绩或接触物理验证 |
| `vision` | 现有 Gazebo + 相机 + YOLO 视觉练习 | 模拟图像识读、检测、深度定位与现有抓取演示 | 会自动进入现有识别抓取流程；不是正式计分线，也不是物理摩擦抓稳验证 |

基础组正式流程不依赖六物件分类识别：编号固定为 1 长方体、2 正方体、3 圆柱体、4 球体、5 三棱柱、6 六棱柱，二维码（例如 `432165` 或 `JAKA1-432165`）只表示抓取顺序。`recognition` 仍保留为独立实验模式，不是正式基础组主流程。

工作台基础练习页的「基础组固定姿态调参」区域会显示当前六个关节角，可移动到输入姿态并记录编号姿态、料盒姿态。全部姿态记录完成后，官方基础模型自动按二维码顺序调用固定关节姿态；未完成标定时自动使用安全的基础笛卡尔流程。没有真机的队伍可以在 Gazebo 调参，有真机的队伍应重新校准后使用同一配置结构。

基础组识别模式会启动已有的 Gemini 305 专用场景：机械臂移动到识别位姿，识别节点发布标框画面与六类形状结果，工作台相机栏显示分类图与匹配统计。原始检测 JSON 和标注图保存在数据目录 `recognition/`。基础练习模式则保留比赛工作流，不会强制机械臂移动到识别位姿；用户可在自行控制相机观察到目标时使用内置预览。

视觉线的工件跟随使用现有仿真逻辑，不应把「工件跟着移动」当作物理夹持正确的证据。实时检测画面刷新也不等同于全程闭环视觉伺服。

**三种模式不能同时运行。** 它们可能使用相同 ROS 节点和控制器；不要在多个终端重复启动。工作台发现已有仿真时会提示冲突，不会自动结束它。请先到原来的终端自行结束那一套，或关闭原工作台自己启动的任务，再启动另一套。不要为了绕过提示而强制并行。

## 建议的基础组练习流程

1. 运行只读自检，确认缺失项。
2. 打开基础模式，查看环境状态和已有进程提示。
3. 启动基础环境，等待实际 ROS 就绪检查；默认关闭 RViz，并在工作台视口内直接嵌入 Gazebo 原生窗口，无截图转码；Wayland 不支持该 X11 嵌入方式时使用独立窗口。
4. 生成题目，然后选择以下一种程序流程（二者不要同时运行）：
   - **参考程序**：点击「运行参考程序」。工作台等待程序连接 MoveIt、收到本轮题目并返回 `program-ready` 后**自动发令**，无需再点手动发令。
   - **学生程序**：在「我的程序」选择自己的文件并运行。确认日志显示程序已收到题目、正在等待发令后，再回控制台点击「发令 / 开始计时」手动发令。当前学生模板**不发送 `program-ready` 握手**，也不会自动发令。
5. 观察运动、日志和结果。练习结束后停止本次任务；需要新题目时再重置/出题。

基础环境使用专用 `jaka_competition_kit/launch/workbench.launch.py`：默认复用比赛 Gazebo 仿真/镜像/判分启动线并关闭 RViz；界面可选 `backend:=mock` 的轻量假硬件/RViz。工作台只会把本工作台进程树拥有的 Gazebo 窗口通过 X11 重挂到原生视口，不会接管外部仿真窗口。

题目种子在启动环境后锁定，更换种子需要先关闭环境再启动。程序速度可在每次启动程序前调整。学生程序尚未启动时，手动发令按钮不可用，避免空计时。

Gazebo 在 X11 下以原生窗口方式嵌入工作台视口，避免逐帧截图造成的延迟与卡顿；Wayland 或嵌入失败时使用独立窗口。RViz（轻量模式）仍使用独立窗口。演示模式只演示软件流程；不产生真实机器人执行证据。程序中的停止也不是实体设备的安全急停，**不要连接真机试验本原型**。

## 当前用户的桌面入口

```bash
bash setup/install-workbench-desktop.sh
```

安装脚本只写当前用户的位置，无需 `sudo`：

- 应用菜单：`${XDG_DATA_HOME:-$HOME/.local/share}/applications/jaka-competition-workbench.desktop`。
- 如果 `xdg-user-dir DESKTOP` 返回一个已存在、独立于家目录的桌面目录，也在那里放一份快捷方式；不会新建缺失的桌面目录。
- 中文名为「基础组学习工作台」，`Terminal=false`。首次桌面启动可能需要右键选择「允许启动」。
- 可重复运行，更新本软件自己生成的入口；遇到同名的其他文件或符号链接会拒绝覆盖。
- 快捷方式指向当前源码路径。移动/删除源码会使入口失效；移动后重新运行安装脚本。
- 不安装 ROS、PyQt、驱动或模型，不修改系统设置，不停止仿真。

要移除入口，仅删除上述自己安装的 `.desktop` 文件；不要删除学生代码或整个数据目录。

## 可编辑的学生示例

### 机械臂基础组模板

源文件：`workbench/examples/student_track1.py`。

先复制到自己的学习目录再修改，例如：

```bash
mkdir -p "$HOME/competition_workspace"
cp workbench/examples/student_track1.py "$HOME/competition_workspace/my_track1.py"
```

在工作台中先生成题目，再选择自己的 Python 文件运行；看到程序等待发令的日志后，回控制台手动发令。与参考程序按钮不同，当前学生模板不提供自动发令握手。由工作台准备 ROS 环境并传入参数，等效程序参数为：

```text
python3 /学生目录/my_track1.py --ros-args -p gripper:=sim -p vel_scale:=0.5
```

这个命令片段只展示参数，不是让尚未加载 ROS 环境的终端直接执行。模板继承现有 `Track1Reference`/`ReferenceBase`，由公共流程等待场景与裁判发令；默认 `verify_only=false` 时才会等发令后执行。

学生主要编辑 `plan_order()`：

1. 从 `scene['qr_png']` 指定的图片实际解码。
2. 校验二维码格式并得到工位顺序。
3. 按工位找到固定训练坐标下的对象，并返回执行列表。

默认示例保持正确顺序。不要从 `qr_order` 或 `qr_payload` 真值字段跳过图像解码；不要随意调换顺序。示例使用固定工位坐标，**不是 YOLO 定位或实时相机识读程序**，也不改动底层碰撞、抓取和 IK 逻辑。

### 不启动 ROS 的顺序练习

```bash
python3 workbench/examples/qr_order_exercise.py JAKA1-246135
```

输出 `2 → 4 → 6 → 1 → 3 → 5`。此示例仅校验已经识读的二维码文本，不解码图片、不连接机器人，也不会启动仿真。

## 安全与成绩边界

- 学生 Python 程序是以当前用户权限运行的可信本地代码，**没有安全沙箱**。不要运行来源不明的文件，Python 程序可以访问和修改用户文件。
- 工作台只请求停止自己管理的子进程，不使用全局清理脚本，不会主动结束已有外部仿真。进程管理不是权限隔离机制；不可信程序自行派生/脱离的进程不在安全保证内。
- 本机成绩用于练习反馈，不用于正式排名。计算性能影响用时；当前判分/真值接口也不是不可信参赛代码的独立评测系统。
- UI 和进程封装不修复既有碰撞、跟踪和判分问题。是否无碰撞、抓取是否可靠，需要独立实测，不能仅凭界面显示「成功」下结论。

## 分发脚本测试

```bash
/usr/bin/python3 -m unittest discover -s workbench/test -p test_distribution.py -v
```

测试使用临时 HOME/XDG 目录和假的解释器，验证参数转发、非项目目录启动、空格/中文/特殊字符路径、退出码、Qt 缺失提示、快捷方式重复安装和拒绝覆盖。可用 `python3-gi` 时，另通过实际 GIO 解析并启动临时桌面入口，验证 Desktop Entry 路径引用；没有 GI 时该项会跳过。

这些测试不写当前用户的真实桌面，不启动 ROS/Gazebo，也不证明机械臂运动或碰撞检查已经通过。

  /usr/bin/python3 -m pytest -q workbench/test jaka_competition_kit/test
